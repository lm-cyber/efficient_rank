# efficient_rank

**Эффективный ранг активаций как критерий выбора ширины слоёв** — проект курса по эффективным моделям глубокого обучения. Проверяем, помогает ли эффективный ранг (ERank) активаций выбирать ширины слоёв лучше равномерного сужения и классического структурного прунинга. Отдельно отделяем этот эффект от выбора конкретных каналов и восстановления весов.

## Главное

Эксперименты: ResNet-20 и Mini-ViT на CIFAR-10/100, pretrained SegFormer-B1 на ADE20K; 630 обучений и fine-tuning на A100, три seed, test открыт только после всех обучений.

- **Распределение ширин по ERank не лучше равномерного сужения.** 0 из 24 заранее заданных сравнений значимы после поправки Бонферрони, средние разницы от −1,3 до +0,5 п.п. Против L1, Network Slimming, Taylor, HRank и SVD весов ERank в середине группы. На ADE20K лучший метод — Taylor, ERank-σ не лучше Uniform, ERank-cov хуже.
- **Ранг ≠ необходимая ширина.** ERank меняется до 75% при масштабировании каналов, которое не меняет функцию сети, и слабо коррелирует с чувствительностью блоков к удалению каналов.
- **Немедленное качество — плохой прокси.** Выбор каналов и компенсация весов меняют accuracy сразу после удаления на ±25 п.п., но после 20 эпох fine-tuning разница не больше 0,05 п.п.
- **Меньше FLOPs ≠ быстрее.** −25% FLOPs замедляют ResNet-20 на A100 на 10–15% во всех режимах исполнения, а ViT с меньшей глубиной при том же бюджете на 44% быстрее.

Подробности — в [отчёте](docs/report.pdf); графики пересобираются из опубликованных CSV скриптом [docs/make_figures.py](docs/make_figures.py).

## Что включено

Код трёх завершённых пулов (CIFAR v1/v2 и ADE20K), дополнительного аппаратного аудита, исходный ноутбук, протоколы, конфигурации, индексы разбиений, архитектуры, журналы обучения, test-предсказания и матрицы ошибок, измерения времени, динамика ранга, итоговые CSV, отчёты и графики. Архивный план Tiny ImageNet сохранён отдельно: его обучения не запускались. Снимки кода сохраняют историю реализации. Датасеты, checkpoint и крупные кеши активаций исключены из Git; они создаются при запуске экспериментов. Исторические протоколы и снимки могут содержать действовавшую при их создании пометку об отложенной публикации.

## Воспроизведение

Использовались Python 3.12, PyTorch 2.5.1 + CUDA 12.1 и NVIDIA A100 80 GB. Точное окружение: [environment.json](runs/erank_models_v2/environment.json).

```bash
git clone https://github.com/lm-cyber/efficient_rank.git
cd efficient_rank
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r experiments_v2/requirements.txt
```

Для пересборки читаемых отчётов из опубликованных измерений GPU и checkpoint не нужны:

```bash
OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4 python3 experiments_v2/readable_report.py
```

Графики презентации и отчёта, затем сами PDF ([Typst](https://typst.app) 0.14):

```bash
python3 docs/make_figures.py
typst compile docs/presentation.typ docs/presentation.pdf
typst compile --root . docs/report.typ docs/report.pdf
```

Полный запуск на GPU 0, включая подготовку данных и повторное обучение: [инструкция](experiments_v2/README.md#execution). Перед ним нужно перенести опубликованные результаты в отдельную папку, как показано в инструкции: маркеры завершённых обучений включены в Git, а соответствующие веса — нет.
