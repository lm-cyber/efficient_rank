# ADE20K / SegFormer-B1

Проверка сжатия обученного сегментатора и идеи выбирать калибровочные изображения с низким эффективным рангом. [Протокол](../experiment_pool_segmentation.md) зафиксирован перед калибровкой и обучением; конфигурация — [config.json](config.json). Эксперимент заменяет очередь Tiny ImageNet, которая не начала обучение.

## Что сравнивается

Внутренние каналы восьми Mix-FFN физически удаляются из Linear → depthwise Conv → Linear. Uniform, Random-width, L1, Taylor и два определения ERank на low/random/high-калибровке сравниваются при одинаковых фактических FLOPs, отдельно на сокращениях около 10% и 20%. Все ширины кратны 8. Основная метрика — pooled mIoU на официальных 2000 validation-изображениях ADE20K; они открываются после всех новых обучений.

60 сжатых кандидатов и 3 несжатых контроля дообучаются по 1500 обновлений, batch 8. Это **около 0,68 эпохи на кандидата**, то есть пилот с ограниченным восстановлением весов. Три seed используют один исходный checkpoint. Эксперимент не проверяет сходимость длительного fine-tuning, обучение с нуля, другие сегментаторы или преимущество над квантизацией/дистилляцией.

Измерение скорости проводится после обучения, на свободной GPU 0: batch 1/8, eager/CUDA Graphs, три раунда. В измеряемый путь входят модель, bilinear resize logits до 512×512 и argmax. Подготовка изображений на CPU, копирование входа и построение графа исключены. Для сравнения качества logits масштабируются до исходного размера разметки: это отличается от фиксированного выхода 512×512 в замерах скорости.

## Окружение

Использовались Python 3.12, NVIDIA A100 80 GB, PyTorch 2.5.1 + CUDA 12.1. Отдельное окружение фиксирует Transformers 4.46.3: имена модулей checkpoint должны совпадать при строгой загрузке весов.

```bash
python3 -m venv .venv-segmentation
.venv-segmentation/bin/python -m pip install -r experiments_segmentation/requirements.txt
```

Все команды ниже выполняются из корня репозитория. Сначала подготовить данные и веса, затем запускать контроллер:

```bash
.venv-segmentation/bin/python -u experiments_segmentation/download.py
.venv-segmentation/bin/python -u experiments_segmentation/controller.py
```

Контроллер сам выбирает физическую GPU 0 по UUID. Он запускает проверки, калибровку, три последовательные очереди seed, итоговую оценку, измерения скорости и отчёт. Все три очереди работают на GPU 0; другие GPU не используются. Одновременно запускать второй контроллер нельзя. Для полного пула требуется достаточно памяти для трёх обучений; проверено на A100 80 GB.

Скачиваются официальный ADE20K и checkpoint `nvidia/segformer-b1-finetuned-ade-512-512`, ревизия `a775b4f5dcb2179e57006dca0e268281306412ef`. SHA256, версия конфигурации, индексы разбиений и снимки исходного кода сохраняются в каталоге результатов. Исходный checkpoint уже обучался на ADE train, включая выделенные сейчас calibration и checkpoint-validation. Официальный validation также мог использоваться авторами checkpoint: он не является новым неизвестным им тестом.

## Состояние, возобновление и результаты

```bash
.venv-segmentation/bin/python experiments_segmentation/progress.py
```

Состояние контроллера: `runs/erank_segmentation_v1/status.json`; текущие шаги seed: `status/s42.json`, `status/s123.json`, `status/s2026.json`; ошибки: `failures/`; журналы: `train_s*.log`. `train_done.json` означает завершённый кандидат, `complete.json` — весь пул, включая оценку, скорость и отчёт. Отсутствие `complete.json` не следует трактовать как завершённое исследование.

Повторный запуск контроллера пропускает завершённые этапы и продолжает обучение от `last.pt`, если предыдущие процессы действительно завершились. Checkpoint сохраняется каждые 500 обновлений. Индексы примеров, flip и генератор dropout восстанавливаются по seed и номеру шага. Детерминированные настройки cuDNN не гарантируют побитового совпадения всех CUDA-операций, включая backward bilinear interpolation.

Для независимого запуска сначала **переименуйте существующий каталог** `runs/erank_segmentation_v1`, сохранив его результаты. Маркеры обучений без соответствующих `.pt` не подходят для продолжения. Данные, веса и крупные кеши исключены из Git.

После завершения в `runs/erank_segmentation_v1/` появятся:

- `findings.md`, `report.md`: выводы и таблицы качества/ресурсов в процентах;
- `results.csv`, `summary.csv`: результаты каждого кандидата и разброс между seed;
- `paired_comparisons.csv`: восемь парных контрастов low против random/Uniform с поправкой на множественные сравнения;
- `class_iou.csv`, `stratified_miou.csv`: диагностика по классам и фиксированным ранг-стратам;
- `calibration.md`, `rank_histogram.png`, `pooled_ranks.png`: индивидуальный и pooled ранг;
- `evaluation/`, `latency/`: матрицы ошибок и исходные серии времени;
- `learning_curves.csv`, `learning_curves.png`: ход восстановления на checkpoint-validation.

Пересборка отчёта после готовой оценки и измерений не требует GPU:

```bash
OPENBLAS_NUM_THREADS=4 OMP_NUM_THREADS=4 .venv-segmentation/bin/python experiments_segmentation/report.py
```

Проверки разметки, preprocessing, mIoU, структурного сжатия и градиентов выполняются до обучения (`verify.py`). Проверку расчёта относительных показателей и отчёта можно отдельно выполнить командой `.venv-segmentation/bin/python experiments_segmentation/verify_report.py`: искусственные входы создаются во временном каталоге и не попадают в результаты исследования.
